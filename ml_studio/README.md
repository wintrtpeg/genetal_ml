# 시계열 ML 스튜디오

도메인에 묶이지 않는 범용 시계열 머신러닝 도구입니다. 데이터를 올리고 타겟만 고르면
전처리·파생변수·모델비교·해석·What-if 까지 한 흐름으로 이어집니다.

로컬 VS Code 에서 Python 으로 돌리고, 화면은 Streamlit 으로 뜹니다.

---

## 설치

**가장 빠른 길** — 압축을 풀고 폴더 안에서

```bash
./run.sh          # macOS / Linux
run.bat           # Windows (더블클릭해도 됩니다)
```

**첫 실행** — 가상환경 생성 → 설치 → 회귀 테스트 → 환경 점검 → 데모 데이터 →
화면 실행까지 한 번에 합니다. 3~10분 걸립니다.

**두 번째부터** — 같은 `run.bat` 을 그대로 더블클릭하면 됩니다. 설치가 끝나 있으면
위 단계를 전부 건너뛰고 **몇 초 만에 화면만 띄웁니다.** 서버가 준비되면
**브라우저가 자동으로 열립니다** — URL 을 복사해 붙여넣을 필요가 없습니다.

| 하고 싶은 것 | 명령 |
|---|---|
| 평소 실행 | `run.bat` (더블클릭) |
| 패키지 재설치·테스트 다시 | `run.bat --full` |
| 화면만 (설치 검사도 건너뜀) | `python scripts/launch.py` |
| **패키지가 꼬였을 때** | `run.bat --repair` |

끝낼 때는 그 창에서 `Ctrl+C` 를 누르세요. 창을 그냥 닫아도 됩니다.
이미 띄워 둔 창이 있으면 다음 포트를 자동으로 잡으므로 충돌하지 않습니다.

**직접 하실 경우**

```bash
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements-core.txt     # 반드시 성공해야 합니다
pip install -r requirements-extra.txt    # 실패해도 무방합니다
python tests/run_tests.py                # 368건 — 여기가 통과해야 결과를 믿을 수 있습니다
python scripts/verify_env.py             # 이 PC 에서만 확인되는 것들 (차트·SHAP·부스팅·SQL)
python scripts/make_demo_data.py         # 가상 데이터 (선택)
streamlit run app/main.py
```

`verify_env.py` 는 `run.bat` 첫 실행에 이미 포함돼 있습니다. 차트 22종·SHAP 3경로·
앙상블 분해·부스팅 3종·SQream 엔진·HTML 리포트를 실제로 한 번씩 돌려 봅니다.
설치된 라이브러리 조합은 PC 마다 다르고, "이 버전에서 그 인자가 사라졌는가" 같은
것은 실제로 불러 봐야 알 수 있어서 두는 창구입니다. **38건 전항목 통과**가
정상입니다. 실패하면 마지막에 나오는 "실패 항목" 블록을 그대로 알려 주시면 됩니다.

건너뜀으로 끝난 항목은 그 라이브러리를 안 깔았다는 뜻입니다. 깔았는데도 안 되면
건너뜀이 아니라 **실패**로 잡히고 버전 조합 문제라고 알려 줍니다 — 이미 깔린
패키지를 다시 깔라는 안내로 돌려보내지 않기 위한 것입니다.

파이썬 **3.10 ~ 3.12** 를 권합니다.

의존성을 두 파일로 나눠 뒀습니다. `requirements-core.txt` 만 있으면 전 단계가
끝까지 돕니다. 부스팅 3종(XGBoost / LightGBM / CatBoost)과 SHAP 은
`requirements-extra.txt` 에 있고, 설치된 것만 자동으로 잡힙니다 — CatBoost 는 용량이
크고 LightGBM 은 윈도우에서 재배포 패키지를 요구하는 경우가 있어, 그것 때문에 전체
설치가 통째로 실패하는 일이 없도록 분리했습니다. SHAP 이 없으면 해석 화면이 순열
중요도로 대체됩니다.

## 문제가 생기면 — 파일 하나로 보내기

```bash
report.bat        # Windows (더블클릭)
./report.sh       # macOS / Linux
```

폴더에 **`diagnostic_report.txt`** 가 생깁니다. 그 파일 하나만 첨부하면 됩니다.
콘솔에서 오류 줄을 찾아 옮겨 적을 필요가 없습니다.

담기는 것 — OS·파이썬·패키지 버전, 회귀 테스트 전문, 실행 환경 점검 전문,
축소 end-to-end 결과. 파일 맨 앞에 통과/실패 요약이 먼저 나옵니다.

**담기지 않는 것** — 데이터 값, 접속 정보, 비밀번호. 컬럼 *이름* 은 오류 메시지에
섞여 들어갈 수 있으니, 사내 규정상 곤란하면 지우고 보내셔도 그대로 쓸 수 있습니다.

`--quick` 을 붙이면 축소 end-to-end 를 건너뛰어 빨라집니다.

### `numpy has no attribute 'long'` 같은 오류가 뜨면

코드 문제가 아니라 **설치된 패키지 조합**이 어긋난 것입니다. numpy 와 scipy 의
버전이 서로 맞지 않으면 이런 형태로 죽고, 그러면 테스트가 무더기로 실패합니다.

```bash
run.bat --repair          # Windows
./run.sh --repair         # macOS / Linux
```

그래도 안 되면 폴더 안의 `.venv` 를 지우고 `run.bat` 을 다시 실행하세요
(설치가 처음부터 돌아 3~10분 걸립니다).

## 저장공간

실행 하나에 `champion_model.joblib` 이 남고, RandomForest·앙상블이면 **수백 MB**
입니다. 그대로 두면 계속 쌓이므로 **화면을 띄울 때마다 자동으로 정리**합니다.

| 기준 | 기본값 |
|---|---|
| 최신 몇 개를 남길지 | 10개 |
| 총 용량 상한 | 2,000MB |
| 보관 일수 | 무제한 |

**새 버전을 처음 켠 실행에서는 실행 결과를 지우지 않습니다.** 기준에 걸리는
것이 있으면 목록만 알려 주고 넘어갑니다 — 기준이 생긴 줄 모르는 상태에서
예전 결과가 사라지면 안 되기 때문입니다. 그 사이에 남길 것을 보관 지정하시면
됩니다. 실제 삭제는 **그다음 실행부터**입니다.

정리는 **시작할 때와 종료할 때 두 번** 돕니다. 시작 정리는 지난번에 남긴 것을,
종료 정리는 이번에 쌓인 것을 치웁니다 (창을 그냥 닫아도 다음 실행의 시작 정리가
받아 줍니다). `run.bat --no-tidy` 로 끌 수 있습니다.

**설정 > 저장공간** 에서 기준을 바꿀 수 있고, 무엇이 얼마나 지워질지 미리 보여준
뒤에 지웁니다. 나중에 다시 열어 볼 실행은 그 화면에서 **보관 지정**해 두세요 —
보관한 것은 어떤 기준에도 걸리지 않습니다.

캐시·중간에 죽은 실행 폴더 같은 찌꺼기는 기준과 무관하게 정리합니다. 다만
`diagnostic_report.txt` 는 보내실 파일이라 **7일이 지나야** 정리 대상이 됩니다.

삭제는 **영구 삭제**입니다 — 휴지통으로 가지 않습니다. 휴지통에 쌓이면 드라이브
용량이 그대로라 목적을 못 이루기 때문입니다.

### 화면을 직접 보실 때 봐 주실 것

자동 점검이 확인하는 것은 **터지지 않는다**까지입니다. 아래는 눈으로만 보이는
것들이라, 쓰시면서 이상하면 알려 주세요.

| 보는 것 | 이상하면 |
|---|---|
| 글자·표가 겹치거나 잘리는가 | 어느 화면 어느 자리인지 (스크린샷이면 더 좋습니다) |
| 조작이 굼뜬가 | 어느 조작에서, 몇 초쯤 |
| 차트가 비거나 축이 이상한가 | 어느 차트, 데이터 규모 |
| 문구가 무슨 말인지 모르겠는가 | 그 문장 그대로 |
| 다음에 뭘 눌러야 할지 모르겠는가 | 어느 단계에서 막혔는지 |

## 화면 흐름

| 단계 | 하는 일 |
|---|---|
| 1. 데이터 | CSV 업로드 또는 SQL 쿼리로 데이터마트 조회 → 시간축 정리 → 타겟 지정 |
| 2. 품질·전처리 | 컬럼별 진단, 제외 후보 제시, 결측·스케일링 방식 결정 |
| 3. 파생변수 | lag·rolling·차분·시간파생 생성 → **품질 리포트 검토 → X 피처 확정** |
| 4. 학습 | 지도학습(모델 병렬 비교 → 챔피언 → 앙상블) 또는 비지도학습(군집·이상탐지·PCA) |
| 5. 예측 | 선택 구간 예측, 실측 대비 라인차트, 잔차 진단(drift·이상점·자기상관) |
| 6. SHAP 해석 | in-sample 기여도, 기간별 dependence plot, 구간 비교, 시점별 분해 |
| 7. What-if | 조건 변경 시나리오, 단일 피처 반응곡선(PDP/ICE) |
| 8. 진단 | 누수 점검·폴드 안정성·잔차·Rolling Backtest·Random vs Time |
| 9. 리포트 | 단독 HTML 리포트, 모델·결과 저장, 재현 기록(manifest) |
| 설정 | 모드 전환, 설정 파일 저장·불러오기, Champion–Challenger |

## 3단계 검토 게이트

파생변수를 만들면 바로 학습으로 넘어가지 않습니다. **품질 리포트를 보고 X 피처를
직접 확정하는 관문**이 하나 있습니다.

```
파생변수 생성 → [품질 리포트 만들기] → 검토 화면 → [이 목록으로 확정] → 학습
```

자동 선별(분산 → 상관중복 → 상호정보)은 **추천**이고, 최종 판단은 사람이 합니다.
도메인 판단이 통계보다 옳은 경우가 많기 때문입니다. 확정하기 전에는 학습 화면이
열리지 않습니다.

검토 화면에서 볼 수 있는 것

- **원본 컬럼별 요약** — `flow 11개 중 9개 선택` 식 롤업. 파생이 많을 때 이 단위가 빠릅니다
- **편집표** — 체크박스로 직접 켜고 끕니다. MI·MI순위·원본·변환·lookback·결측률·자동 판정 사유
- **필터** — 원본별 / 변환 종류별 / 이름 검색 / "자동 추천에서 탈락한 것만"
- **일괄 선택** — 자동 추천대로 · 전체 · 해제 · 원본 컬럼만 · MI 상위 30
- **위험 경고** — 상관 중복 동시선택, 분산 0, 결측 과다, 정보량 0

경고는 **막지 않습니다.** "이 태그는 물리적으로 반드시 들어가야 한다"는 판단을
도구가 뒤집으면 안 되니까요. 다만 무엇을 감수하는지는 알려 드립니다.

### 여기서 조심한 것

검토 화면의 숫자는 **전부 학습 구간에서만** 계산합니다. 알고리즘이 홀드아웃을 못 보게
막아 놓고 사람에게는 전체 구간 통계를 보여주면, 그 표를 보고 피처를 고르는 순간
**사람이 누수 경로**가 됩니다. 검증·Final Unseen 구간을 오염시켜도 검토 표가 바뀌지
않는지 테스트로 확인합니다.

사람이 자동 추천을 바꾸면 그 내용이 감사 이력과 `manifest.json` 에 사유와 함께 남습니다.

```
feature   status              reason
flow      removed(수동제외)    사용자가 직접 제외 (자동 판정: MI 상위 1위)
valve     selected(수동추가)   사용자가 직접 추가 (자동 판정: MI 순위 46위 (상위 25 밖))
```

## Auto 모드 — 한 번에 실행

Auto 모드에서는 1단계에서 타겟을 고르면 실행 버튼이 나타납니다. 품질 진단부터
Final Unseen 평가까지 이어서 돕니다.

```python
# UI 없이도 같은 것을 돌릴 수 있습니다 (Dataiku Scenario 등)
from core import pipeline
res = pipeline.run_auto(df, "y_output", pipeline.AutoConfig(top_k=40))
print(res.champion, res.unseen_scores)
print(res.decisions)     # 무엇이 어떻게 정해졌는지
```

**자동화되는 것은 '사람이 버튼을 누르는 일' 이지 '검증을 생략하는 일' 이 아닙니다.**
3분할, gap 자동 설정, 선별 구간 추적, 폴드 내부 선별, Unseen 1회 접근이 그대로
작동하고, 누수 점검을 통과하지 못하면 학습 전에 멈춥니다.

사람이 고르던 값은 기본값으로 대체되지만, 무엇을 어떻게 정했는지 `decisions` 표에
근거와 함께 남습니다. 바꾸고 싶은 항목이 있으면 Guided·Expert 모드로 그 단계만
다시 하면 됩니다.

## 결과를 믿기 위한 장치

이 도구는 "얼마나 잘 맞나"보다 **"그 숫자를 믿어도 되나"** 에 무게를 둡니다.

| 장치 | 하는 일 |
|---|---|
| 3분할 | `[Train][Validation][Final Unseen]`. Validation 으로 모델을 고르고, Unseen 은 최종 보고에만 씁니다 |
| Unseen 1회 접근 | `UnseenGuard` 가 두 번째 접근을 예외로 막습니다. 규율이 아니라 코드로 강제합니다 |
| 분할 단일화 | 분할은 3단계에서만 정합니다. 학습 화면에서 다시 나누면 선별 구간이 평가 구간으로 넘어갑니다 |
| 선별 구간 격리 | 피처 선별에 쓴 행 인덱스를 추적해 평가 구간 침범을 잡습니다 |
| gap 점검 | 파생 lookback 보다 gap 이 좁으면 실패로 막습니다 |
| 폴드 내부 선별 | 선별을 Pipeline 안에 넣어 폴드마다 다시 fit 합니다. 폴드 간 Jaccard 로 안정성을 봅니다 |
| Y 파생 차단 | Y 의 과거값은 X 로 만들지 않습니다. 코드 수준에서 막혀 있습니다 |
| 앙상블 자동채택 | 단일 최고 모델 대비 임계값(기본 3%) 이상 좋아질 때만 챔피언이 됩니다 |
| Random split 격리 | 진단으로만 제공하고, 평가 경로 유입은 예외로 막습니다 |
| nested CV 탐색 | 하이퍼파라미터를 고른 구간과 점수를 낸 구간을 분리합니다 (기본 OFF) |

`python tests/run_tests.py` 로 368건이 이 장치들을 검증합니다.
누수가 있으면 **실패하도록** 짜여 있어서, 전부 통과해야 결과를 믿을 수 있습니다.

## SHAP 기간 보기

SHAP 값은 시점마다 따로 계산됩니다. 그래서 한 번 계산해 두면 기간을 바꿔 볼 때
다시 돌릴 필요가 없습니다. 화면도 그 구조를 따릅니다.

| 조작 | 성격 |
|---|---|
| 계산 범위 | 무거움. 버튼을 눌러야 돕니다. 대상(학습/홀드아웃/전체), 표본 상한, 날짜 범위를 정합니다 |
| 표시 기간 | 가벼움. 슬라이더나 프리셋(최근 7·30·90일)을 움직이면 즉시 다시 그립니다 |

표시 기간을 바꾸면 기여도 순위, dependence plot, 기여도 추이, 시점 분해가
모두 그 기간 기준으로 다시 계산됩니다. 기준값(base value)은 모델 전체의 기대값이라
기간과 무관하게 고정입니다.

**dependence plot 색상**

- `상호작용` — 상호작용이 강한 다른 피처 값으로 색을 입힙니다 (자동 선택 가능)
- `시점` — 시간 순서로 색을 입힙니다. 기간 안에서 관계가 흘러가는지 봅니다
- `단색` — 형태만 봅니다

**구간 비교**

두 구간(A/B)을 골라 겹쳐 그립니다. 같은 피처 값인데 SHAP 값이 다르면
그 사이에 설비나 운전 조건이 달라졌다는 신호입니다. 함께 나오는 막대는
구간별 기여 비중(%)이고, `변화` 열이 큰 순으로 정렬해 어떤 인자가
주도권을 넘겨받았는지 보여줍니다.

```python
from core import explain

res  = explain.compute_shap(pipe, X_train)              # 한 번만 계산
view = explain.slice_period(res, "2025-03-01", "2025-03-31")   # 기간 자르기
dep  = explain.dependence_data(view, "flow", "temp")
cmp  = explain.dependence_by_periods(res, "flow", [
    ("개조 전", "2025-01-01", "2025-02-15"),
    ("개조 후", "2025-02-16", "2025-04-30"),
])
shift = explain.period_shift(res, periods)              # 기여 비중 이동
```

접속 정보를 넣고 SELECT 문을 화면에서 직접 작성합니다. 내부적으로는 이렇게 돕니다.

```python
import sqlalchemy as sa
engine = sa.create_engine(url)          # 화면에서 조립한 접속 URL
df = pd.read_sql(query, engine)         # 화면에서 작성한 SELECT 문
```

## 설계상 지키는 것

### Y 의 과거값은 X 로 쓰지 않습니다

`FeatureConfig.allow_target_derived = False` 가 기본이고, 생성 후에도 출처 대장을 근거로
한 번 더 검사합니다. 위반하면 `TargetLeakage` 예외로 즉시 멈춥니다.

정확도만 보면 Y lag 를 넣는 쪽이 거의 항상 높게 나옵니다. 그런데 그 모델은
"직전 Y 가 이랬으니 지금도 비슷할 것"을 학습한 것이라, X 를 바꿔서 Y 를 움직이려는
What-if 나 원인 분석에는 쓸 수 없습니다. 이 도구는 후자를 우선합니다.

단기 예측 정확도가 목적이라면 `allow_target_derived=True` 로 바꾸고
`FeatureConfig.lags` 에 타겟을 포함시키면 됩니다. 다만 그 순간 6·7번 화면의 해석은
의미가 달라집니다.

### 데이터 누수 차단

세 층위로 막습니다.

1. **분할** — 홀드아웃은 항상 시간축 마지막 구간입니다. 학습·튜닝·피처선별 어디에서도
   보지 않습니다. 교차검증은 rolling origin(`TimeSeriesSplit`) 만 씁니다. 셔플 옵션은 없습니다.
2. **전처리** — 임퓨터·스케일러·인코더가 전부 `sklearn.Pipeline` 안에 들어가 폴드마다
   다시 fit 합니다. 전체 데이터로 미리 처리해 두지 않습니다.
3. **파생변수** — 중앙정렬 rolling, 역방향 shift, 전체 구간 통계를 만들지 않습니다.
   lag 길이만큼 gap 을 두어 검증 구간을 넘겨보지 못하게 합니다.

학습 직전에 점검표를 띄우고, 하나라도 실패하면 학습 버튼이 동작하지 않습니다.
`tests/test_leakage.py` 가 이 장치들을 회귀 테스트합니다.

```bash
pytest tests/ -v          # 또는 python tests/run_tests.py
```

### 스태킹의 메타학습기

`StackingRegressor` 의 기본 `cv` 는 KFold 라 미래 폴드가 메타학습에 섞입니다.
`core/train.py` 에서 `TimeSeriesSplit` 을 명시적으로 넘깁니다.

## 파생변수를 LLM 없이 만드는 이유

시계열 파생변수는 형태가 정해져 있습니다. lag, rolling 통계, 차분, 지수이동평균,
시간 주기성, 피처 간 비율·차이. 이 조합을 전부 만든 뒤 분산·상관·상호정보량으로
추리는 편이 LLM 에게 물어보는 것보다 빠르고 재현됩니다.

LLM 이 보탤 수 있는 건 "이 두 태그를 나누면 물리적으로 의미가 있다" 같은 도메인 판단인데,
그건 3번 화면의 조합 선택에서 사람이 직접 고르는 쪽이 낫습니다. 제조 데이터를
외부 모델에 넣지 않아도 된다는 점도 이 방향과 맞습니다.

## 읽을 때 주의할 것

**SHAP 은 인과가 아닙니다.** 모델이 학습한 통계적 관계입니다. 두 태그가 늘 함께 움직이면
둘 중 하나에 기여도가 몰릴 수 있고, 그게 물리적 원인이라는 뜻은 아닙니다.

**What-if 는 모델의 관점입니다.** 한 피처만 바꾸면 실제로는 함께 움직였을 다른 피처가
고정된 채로 계산됩니다. 물리적으로 종속된 값은 화면의 연동 설정으로 같이 움직여야 합니다.
학습 데이터 범위를 벗어난 값은 외삽 경고가 뜹니다.

**과적합 확인은 학습 대비 홀드아웃 차이로 봅니다.** 4번 화면의 과적합 점검 표에서
차이가 크면 그 모델은 학습 구간에만 맞춰진 것입니다.
